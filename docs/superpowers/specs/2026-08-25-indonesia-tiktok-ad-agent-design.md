# AdFlow 跨境电商产品广告 Agent 设计规格

**文档状态：** 2.0 已确认产品基线，运行架构已补充 Windows 常开主机方向
**版本：** 2.0
**更新日期：** 2026-08-27
**首发市场：** 印度尼西亚
**首发平台：** TikTok

## 1. 产品目标

AdFlow 是面向公司运营人员的浏览器广告生产工作台。用户不需要掌握 AI、提示词工程或视频工具，只需提交素材、产品资料和自然语言要求，系统即可完成素材理解、广告策划、方案确认、执行、改稿和成片交付。

产品由两条独立生产线和一套共享基础能力组成：

1. **生产线 A：已有素材智能剪辑。** 理解多条完整视频，提取有价值片段，重新策划并剪成一条新的广告。
2. **生产线 B：产品图到 AI 广告视频。** 从产品主图建立产品资产、脚本和分镜，再逐镜头生成视频并合成广告。
3. **共享基础能力。** Agent 编排、资产库、审核工作台、版本记录、实际调用记录、可替换执行适配器和未来可安装 Skill。

开发顺序固定为：

`先完成生产线 A -> 再完成生产线 B -> 最后扩展批量生产与发布闭环`

首个版本聚焦单任务生产和人工可审核结果，不以无人值守批量发布为目标。

## 2. 核心设计原则

1. **创意优先，事实为硬边界。** Agent 应最大化利用 AI 进行素材理解和广告创意，但不能擅自改变已确认的产品包装、Logo、颜色、容量和事实。
2. **自然语言是主要输入。** 用户通过一句话描述目标、时长、语言、节奏和重点；Agent 解析后展示理解结果。不得用重复勾选项替代语义理解。
3. **Agent 决策，执行器执行。** Codex Agent 负责理解、策划、选片、解释和生成协议；FFmpeg、Remotion、剪映和视频模型只执行已确认任务。
4. **先确认方案，再产生高成本结果。** 产品事实、资产、分镜、剪辑时间线和低清预览均保留人工确认。
5. **协议和供应商可替换。** 产品不绑定单一 Agent 框架、模型中转站、视频模型或渲染工具。
6. **可追溯、可修改、可恢复。** 每一步保存输入、输出、确认记录和版本关系；失败只重做受影响部分。
7. **能力边界诚实。** 不把静态演示、固定规则混剪或 Fake Provider 描述为真实 AI 自动剪辑；不承诺万能去水印或平台审核必过。

## 3. 用户、入口和任务类型

### 3.1 用户与访问

- 公司授权邮箱和密码登录，不提供公开注册。
- 浏览器跨设备访问；任务、素材、确认状态和版本保存在云端。
- MVP 可由同一运营人员完成方案确认和最终批准，但分别记录两个动作，为后续职责分离预留接口。

### 3.2 两种独立生产任务

#### 生产线 A：已有素材智能剪辑

用户上传一条或多条视频，Agent 完整理解素材并重新策划广告。允许用户指定必须使用的素材或片段；其他素材由 Agent 自由筛选，低价值、重复或无关片段可以完全舍弃并展示原因。

#### 生产线 B：产品图到 AI 广告视频

用户上传产品主图和已知产品资料。系统建立高清产品母版和可复用资产，再生成广告脚本、九宫格分镜、镜头执行卡和 MiniMax 视频任务。

两条生产线共享工作台和资产库，但拥有独立工作流。生产线 A 不会因为没有产品图而被强制进入生产线 B；生产线 B 也不要求用户先上传本地视频。

## 4. 自然语言需求与硬约束

典型输入：

> 把这两个素材重新剪成 30 秒的印尼 TikTok 广告，节奏快一点，突出产品多功能，去掉中文声音，改成印尼语字幕和女性配音。

Agent 将其解析为业务可读任务单：

- 用户硬约束：目标时长、目标画幅、必须使用片段、禁用内容。
- 广告目标：产品重点、目标人群、使用场景、行动号召。
- 市场与平台：印度尼西亚、TikTok 或用户指定平台。
- 声音方案：原声、环境音、背景音乐、配音语言和音色。
- 文字方案：字幕语言、原硬字幕和角标处理建议。
- 创意偏好：节奏、情绪、结构和需要突出的画面。

解析结果必须先展示给用户确认或修改。目标时长不能固定为 30 秒或 45 秒；用户没有指定时，Agent 才根据内容给出建议。

## 5. 输出画幅与多版本

画幅是任务级硬约束，不固定为 9:16：

- `9:16`：TikTok、Reels 和其他竖屏内容。
- `16:9`：横屏广告和 YouTube 等场景。
- 协议预留 `1:1`、`4:5` 和其他后续比例。

系统根据平台推荐默认画幅，但用户可以手动指定。比例适配不得直接拉伸画面，必须逐镜头重新构图：

- 识别产品、人物、动作、原字幕和角标位置。
- 采用智能裁切、主体跟踪、背景扩展、补边或多画面布局。
- 重新计算字幕、贴纸和行动号召的安全区。
- 无法合理适配时提示换片段，而不是隐藏问题。

同一项目可以输出多个比例版本。它们共享素材理解和广告结构，但分别保存镜头构图、字幕布局、低清预览和高清成片。修改画幅会使相关镜头构图确认失效，并要求重新生成预览。

## 6. 生产线 A：已有素材智能剪辑

### 6.1 完整流程

`上传视频与自然语言要求 -> 完整素材理解 -> 素材价值地图 -> Agent 广告策划 -> 剪辑执行时间线 -> 人工确认 -> 完整低清预览 -> 自然语言改稿 -> 高清执行 -> 自动检查 -> 人工批准与下载`

### 6.2 完整素材理解

系统不能只按固定间隔抽几张图。每条视频都需要组合分析：

1. **技术预检：** 格式、损坏、时长、分辨率、方向、帧率和音轨。
2. **镜头边界检测：** 对全片建立场景和动作变化时间码。
3. **ASR：** 识别口播语言、文本、说话时间和置信度。
4. **OCR：** 识别硬字幕、价格、品牌、包装文字和角落标识的位置与时间。
5. **多模态视觉理解：** 理解产品、人物、动作、使用场景、问题、效果和前后关系。
6. **加密分析：** 在产品露出、动作变化、前后对比和场景切换处增加分析密度。
7. **质量与重复判断：** 模糊、抖动、遮挡、停顿、重复动作和无效片段。

识别结果不是绝对事实。系统保存时间码、证据和置信度；低置信度项目必须交给用户判断。

### 6.3 素材价值地图

后台保存完整分析，前台默认只展示运营需要决策的重点：

- 高价值：适合开场、产品锚点、演示、对比或收尾。
- 可用：有信息价值，但不一定进入当前广告。
- 重复：与其他片段表达相同，默认可舍弃。
- 低质：模糊、遮挡或动作不完整。
- 风险：原硬字幕、固定角标、疑似第三方品牌或其他需要人工检查内容。

用户点击时间块或缩略图后，页面展开来源时间、识别证据、置信度、Agent 判断理由和处理建议。页面不直接铺满逐秒分析数据。

### 6.4 Agent 广告策划与选片

Codex Agent 同时读取：

- 用户要求和硬约束。
- 完整素材分析和素材价值地图。
- 用户指定的必须使用片段。
- 市场、平台、产品资料和广告目标。

Agent 先确定广告结构，再选片段。例如：

`产品钩子 -> 多场景演示 -> 核心效果或功能总结 -> 产品与行动号召`

Agent 不按原视频顺序或素材 A/B 机械交替。每个使用或舍弃决定都要有业务理由。

### 6.5 剪辑执行时间线

用户确认的是业务可读方案，而不是代码。时间线至少展示：

- 目标时长、画幅、平台、语言和广告结构。
- 每个镜头的成片位置、来源素材、原始入点和出点、使用长度。
- 选用或舍弃理由。
- 加速、慢放、裁切、主体跟踪、转场和视觉包装。
- 原声、环境音、背景音乐、配音与音量方案。
- 字幕、原硬字幕和角标处理方案。
- 需要人工选择的处理预览。

只有方案确认后，执行器才能生成低清预览。

### 6.6 声音、字幕和角标

- Agent 从自然语言和目标市场理解本地化需求，不要求用户再次勾选相同控制项。
- 中文口播可以静音或替换；环境音可按广告需要保留；背景音乐单独判断。
- 原硬字幕和角标先自动检测，再提出裁切、覆盖、局部修复、换片段或弃用方案。
- 系统不承诺自动无痕去除。文字靠近产品、人物或关键动作时，应优先展示可比较预览。
- 执行前由用户审核原声、配音、字幕、背景音乐和画面文字处理。

### 6.7 完整低清预览

低清预览必须接近最终效果，而不是静态分镜播放。它与高清成片使用同一份已确认时间线，并包含：

- 完整镜头顺序、节奏和目标时长。
- 草稿配音、字幕、原声和背景音乐处理。
- 转场、视觉包装和画幅构图。
- 原硬字幕和角标处理效果。

低清预览仅降低分辨率和码率，以降低等待和重做成本；不得省略影响判断的关键效果。

### 6.8 自然语言改稿与版本

用户可直接输入：

> 开头再快一点；自行车镜头缩短 2 秒；门锁镜头提前；结尾产品停留 3 秒。

Agent 应：

1. 判断受影响的镜头、配音、字幕和总时长。
2. 生成新的时间线版本。
3. 展示新增、删除、移动和时长变化，以及总时长如何保持约束。
4. 等待用户确认变更。
5. 只重新执行受影响的预览部分或必要完整预览。

旧方案永久保留为可对比、可恢复版本，不能覆盖。

### 6.9 执行架构

- **低清预览：** FFmpeg + Remotion 快速执行。
- **高清成片：** 优先使用剪映执行适配器，以使用会员模板、特效或剪映独有能力。
- **失败回退：** 剪映不可用或执行失败时，FFmpeg + Remotion 仍可输出可审核高清版本。

若使用剪映桌面端，需要一台安装并登录剪映的专用执行电脑保持在线。运营人员可在其他电脑通过网页提交和审核，不需要在自己的电脑运行剪映。

### 6.10 成片审核与交付

高清执行后先自动检查：

- 目标时长、画幅、分辨率和编码。
- 黑帧、卡帧、音画不同步和缺失资源。
- 配音与字幕是否缺失或时间错位。
- 字幕和产品主体是否位于目标平台安全区。
- 原口播、硬字幕和角标是否按确认方案处理。
- 实际成片是否与已确认时间线一致。
- 产品和关键卖点是否清楚，以及需要人工判断的平台风险。

用户必须完整观看并批准。MVP 不自动发布到 TikTok。交付内容包括：

- 高清 MP4 成片。
- 字幕文件。
- 配音音频。
- 最终剪辑时间线及版本记录。
- 可编辑剪映工程或草稿包，仅在执行适配器可靠支持时提供。

## 7. 生产线 B：产品图到 AI 广告视频

### 7.1 完整流程

`上传产品主图 -> 图片质量门与可选高清母版 -> 产品事实锚点 -> AI 资产候选 -> 人工确认并进入资产库 -> 印尼广告脚本 -> 九宫格分镜与镜头执行卡 -> 人工确认 -> MiniMax 逐镜头生成 -> 镜头审核 -> 最终合成与成片审核`

### 7.2 图片质量门

图片质量检测由三部分协作：

- **确定性程序：** 分辨率、模糊、曝光、裁切、文件完整性和主体占比。
- **可替换多模态视觉模型：** Logo、标签、容量、瓶型、包装文字和是否适合后续资产生成。
- **Codex Agent：** 汇总结果、解释问题、建议直接使用、修复、重建或补图。

“检测可以继续”不代表必须直接进入下一步。用户可以主动选择生成更高清的产品母版。

### 7.3 高清产品母版

- 仅分辨率低或压缩严重时，优先超分、降噪和锐化，避免重新设计产品。
- 清晰度不足但产品结构和关键文字可辨时，可用参考图生图模型生成高清重建候选。
- Logo、容量或包装文字无法辨认时，不允许模型将猜测直接写入产品事实；系统要求用户确认或补充资料。
- 高清候选永远不覆盖原始图。用户选中并确认后，它才成为后续资产和视频模型引用的产品母版。

### 7.4 产品事实锚点

事实锚点保存后续生成不得擅自改变的内容，例如：

- 包装轮廓、材质和颜色。
- Logo、品牌名、容量和可辨认标签。
- 喷头、瓶盖或其他结构特征。
- 用户提供的产品事实、卖点和禁止改变项。

AI 只能提出候选，用户负责确认或纠正。推测的侧面和背面不能升级为真实产品事实。

### 7.5 AI 资产库

资产层级为：

`原始商品图 -> 高清修复/重建候选 -> 已确认高清产品母版 -> 三视图/多角度/透明底/手持/多场景资产 -> 已确认资产库`

只有正面图时，AI 可以生成侧面、背面和多视图候选，但需要真实背标或包装信息的镜头必须补充真实资料。图片像素中不嵌入“AI生成”字样；来源、模型、参考图和确认状态保存在后台元数据中。

### 7.6 印尼广告脚本

Codex Agent 根据已确认产品事实、市场、受众、卖点和广告目标，生成广告结构、印尼语配音稿和字幕初稿。用户可以修改卖点、语气、顺序和禁用内容。脚本是后续九宫格分镜的叙事骨架。

### 7.7 九宫格分镜和两层提示词

第一层是运营人员确认的“镜头执行卡”：

- 镜头目的、画面内容和人物动作。
- 产品参考资产和必须保持一致的特征。
- 构图、镜头运动、时长、字幕和配音。
- 禁止改变项和失败判定标准。

第二层是 Agent 自动编译的模型提示词：

- 将镜头执行卡转换为 MiniMax 适配语言。
- 附加参考图、产品一致性约束、负面约束、比例、时长和模型参数。
- 默认折叠，但允许高级用户展开查看。

提示词确认不新增第七个主流程节点。用户确认某个九宫格分镜时，同时确认其镜头执行卡和 Agent 对需求的理解。产品资产、脚本或要求变化时，对应镜头确认自动失效。

### 7.8 MiniMax 逐镜头生成

Codex Agent 保存完整项目上下文，但 MiniMax 只接收当前镜头需要的信息：

`已确认分镜图 + 产品参考资产 + 镜头级提示词 + 一致性约束 + 时长/画幅/镜头参数`

每个镜头独立生成和审核。失败只重做对应镜头，不盲目重做整条广告。包含产品的镜头优先使用已确认产品资产；产品变形时停止无意义重试，退回资产、提示词或后期合成路径。

## 8. 统一协议与组件边界

### 8.1 协议

- `ad_project.v1`：用户要求、市场、平台、产品事实、资产引用和版本。
- `analysis_map.v1`：视频时间码、ASR、OCR、多模态标签、质量、置信度和素材价值。
- `edit_plan.v1`：生产线 A 的镜头、轨道、字幕、配音、处理操作和确认记录。
- `generation_plan.v1`：生产线 B 的脚本、分镜、执行卡、模型提示词、参考资产和生成状态。

协议必须可校验、可版本化、可审计。执行器只接收允许字段，不能执行 Agent 返回的任意命令或任意文件路径。

### 8.2 组件职责

- **Codex Agent：** 主控编排、需求理解、素材分析协调、广告策划、选片、脚本、分镜、提示词编译、差异解释和工具调用。
- **Agent 适配层：** 保持 Codex 优先，但允许替换为其他 Agent 框架。
- **视觉模型适配层：** 图片和视频内容理解，接口可替换。
- **图片生成/编辑适配层：** 高清产品母版和产品资产生成。
- **MiniMax 适配层：** 已确认分镜的逐镜头视频生成。
- **FFmpeg：** 裁切、拼接、音轨、转码和基础媒体处理。
- **Remotion：** 动态字幕、贴纸、转场、品牌包装和可编程预览/成片。
- **剪映执行适配层：** 高清成片优先路径和可编辑草稿交付。
- **配音适配层：** 接入公司现有配音工具，保持供应商可替换。

## 9. 模型中转站与密钥

系统通过供应商适配层接入用户选择的中转站，不把配置写死。配置项包括：

- API Base URL。
- 鉴权方式。
- 视觉模型名称。
- 图片生成/编辑模型名称。
- 请求和响应映射。
- 超时、重试和安全错误映射。

不能提取或迁移 Codex 桌面应用内部认证。真实 Key 只配置在后端环境变量、Cloudflare Secret 或等价密钥系统中；不得出现在前端、代码、文档、日志、`.env.example` 或 Git。系统只能报告配置状态，不能返回 Key 值。

## 10. 跨设备与可替换运行架构

当前优先部署目标是一台公司长期在线的 Windows 台式机：

- Windows 同时承载前端、公司登录入口、API、Agent Harness、轻量任务编排和访问控制。
- 本地 SQLite 或等价数据库保存用户、任务、协议、确认记录、版本和调用记录。
- Windows 数据目录保存源素材、中间产物、预览和成片；业务增长后可替换为 OSS/R2 等对象存储。
- 外部模型通过 Windows 后端 API 调用，本地不运行大模型、图片模型或视频模型。
- FFmpeg/Remotion 作为本机独立进程执行媒体任务。
- 剪映桌面自动化运行在同一台安装并登录剪映的 Windows 执行机上，并保持与 Web/API 进程隔离。
- 先验证本机和局域网访问，再使用 HTTPS 安全隧道提供跨网络访问。

运行层必须保持可替换。未来仍可迁移为 Cloudflare 或国内云前端/API、D1/云数据库、R2/OSS 和独立 Windows 剪映执行节点，但不得让这些基础设施改变产品协议和画布血缘。

域名或隧道只提供访问地址，不提供模型计算资源。运营人员可以从任意授权电脑进入网页；只要 Windows 主机保持在线，页面关闭后任务仍可继续。主机断电、休眠或断网期间服务不可用，因此必须设置开机自启、健康检查和数据备份。

## 11. 状态、失败与恢复

主状态按生产线适配，但至少包括：

`草稿 -> 已上传 -> 分析中 -> 待方案确认 -> 预览生成中 -> 待预览审核 -> 高清执行中 -> 待成片审核 -> 已批准`

生产线 B 还包括：

`待产品事实确认 -> 待资产确认 -> 待脚本/分镜确认 -> 镜头生成中`

规则：

- 每一步保存输入版本、输出位置、执行次数、错误类别和确认人。
- 页面关闭、网络中断或换电脑不终止云端任务。
- 每一步使用幂等标识，避免重复点击创建重复任务或调用。
- 成功结果单独保存；失败只重做受影响镜头或步骤。
- 失败必须解释发生在哪一步、影响什么、用户可以执行什么恢复动作。

## 12. 实际调用记录与费用边界

- 不展示无法可靠判断的预计费用、任务估价或虚构月度金额。
- 本地分析、FFmpeg 和 Remotion 不在业务页面制造推算费用。
- 真实生图、视频生成或配音 API 只有在供应商返回可信费用时才记录实际消费。
- 供应商不返回准确费用时，只记录模型、调用次数、输入输出摘要和任务结果。
- 重复提交、刷新、重试和回退必须避免重复调用；真实付费动作前保留人工确认。
- 调用记录和版本关联，不覆盖历史结果。

## 13. 浏览器工作台

1. **任务列表：** 产品图头像、生产线、市场、创建人、状态和更新时间。没有产品图时使用视频代表帧，不使用产品名称首字母假装图片。
2. **新建任务：** 选择生产线，上传对应素材，用自然语言描述要求，并确认 Agent 解析结果。
3. **素材智能分析：** 素材价值地图、片段证据、置信度和处理建议。
4. **剪辑方案：** 广告结构、精确时间线、声音/字幕/角标方案、自然语言修改和人工确认。
5. **产品资产画布：** 原图、高清母版、事实锚点、资产候选、脚本、九宫格、镜头执行卡和生成状态。
6. **预览与审核：** 完整低清预览、自然语言改稿、版本差异、单镜头重做和高清确认。
7. **成品与版本：** 播放、自动检查、人工批准和交付文件下载。

界面默认使用业务语言。普通运营人员不需要看到模型参数或底层命令；技术提示词可折叠查看，但不要求逐字确认。

## 14. TikTok 调性与风险检查

系统在剪辑方案确认前和成片批准前分别检查：

- 前几秒是否有清晰钩子，产品和广告目的是否明显。
- 节奏、镜头密度和画幅是否符合目标平台内容形式。
- 字幕是否位于安全区，印尼语字幕和配音是否一致。
- 是否存在无法确认的夸大功效、价格、认证或前后对比表达。
- 是否出现第三方品牌、角标、原硬字幕或音乐使用风险。
- 产品包装、Logo、颜色、容量和事实是否保持一致。

上传素材不设置授权确认或权限阻断，所有上传素材均可进入分析和剪辑。风险提示用于人工判断和修改，不等于平台合规保证；最终审核权属于用户和发布平台。

## 15. 安全

- 密码使用不可逆哈希，登录会话使用安全 Cookie 和过期机制。
- 上传、查看、下载、确认和批准动作记录公司身份和时间。
- 上传类型、大小、文件名和媒体内容在服务端校验；对象存储使用不可预测键和限时访问地址。
- API Key 只在服务端使用，错误、日志和响应不能包含认证头、原始密钥或敏感供应商响应。
- 渲染器只读取当前任务允许的对象和协议字段，禁止任意路径和命令执行。
- 素材和生成结果保留期限在部署前由公司确定。

## 16. MVP 验收标准

### 16.1 生产线 A

- 用户可上传两条或更多真实视频并提交自由文本剪辑要求。
- 系统形成覆盖全片的素材理解结果，并展示可交互素材价值地图。
- Agent 根据要求重新策划广告，不按固定规则或原片顺序机械拼接。
- 用户可指定必须使用片段，其他片段由 Agent 筛选并解释理由。
- 剪辑时间线精确显示来源、切点、长度、处理、声音和字幕。
- 用户确认后生成与最终效果接近的完整低清预览。
- 自然语言改稿会生成可确认差异和新版本，旧版本可恢复。
- 9:16 和 16:9 至少各验证一个版本，不拉伸主体，字幕位于安全区。
- 高清成片优先通过剪映执行；剪映不可用时，自有渲染路径仍能输出可审核版本。
- 成片通过技术检查和人工批准后可下载。

### 16.2 生产线 B

- 单张产品主图可完成质量检测，并允许用户主动生成高清产品母版。
- 原始图、高清候选、确认母版和生成资产拥有清晰来源与状态。
- 产品事实锚点需人工确认；推测背面不被当成真实事实。
- 能生成并确认资产候选、印尼广告脚本、九宫格和镜头执行卡。
- Agent 将执行卡编译成模型提示词，并把当前镜头所需上下文发送给 MiniMax。
- 至少一个真实短镜头通过 MiniMax 生成并完成产品一致性审核。
- 失败只重做对应镜头；产品变形时停止盲目重试。
- 已确认镜头可合成为完整预览并进入统一成片审核。

### 16.3 共享能力

- 授权用户可跨设备登录、恢复任务和查看版本。
- 页面关闭后云端任务继续；失败状态提供可理解恢复动作。
- 真实 Key 不进入前端、仓库、文档或日志。
- 不展示不可信的预计费用；实际调用记录与任务版本关联。
- 当前生产路径不使用未标识的 Fake Provider 冒充真实模型分析。

## 17. 实施前技术验证

以下项目属于实施计划中的技术验证，不改变本设计的产品边界：

- 用户中转站的 Base URL、鉴权、模型名称、请求格式和多模态能力。
- MiniMax 当前可用模型、参考图限制、时长、画幅、并发、价格和内容策略。
- 公司现有配音软件的接口、授权方式和商用边界。
- 剪映桌面自动化的稳定性、会员能力可调用范围、草稿格式和失败恢复。
- FFmpeg/Remotion 在候选渲染环境中的字体、媒体依赖、临时磁盘和长任务表现。
- 最新 TikTok 印度尼西亚广告规则、字幕安全区和品类限制。
- 公司授权邮箱维护、任务保留期限和最终审核负责人。

## 18. 已验证原型与真实能力边界

已通过用户确认的交互方向：

- 产品概览与两条生产线结构。
- 生产线 B 六节点解释页。
- 生产线 A“后台完整分析、前台素材价值地图、详情可展开”。
